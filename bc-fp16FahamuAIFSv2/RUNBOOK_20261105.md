# Runbook: 220-member same-date hindcast for 5 Nov, on Colab

The hindcast that bias-corrects the AIFS-ENS v2 forecast started on 2026-11-05: AIFS-ENS v2
run from ERA5 on 5 Nov of each year 2006–2025, 11 members per year (control + 10
EDA-perturbed) = **220 runs**. This runbook goes from the starting-state pkls to the
corrected forecast, with every script, data source, credential and command. The control-only
20-member version built on the GPU box is in `runbook_20261111.md`. The Colab design,
GPU choice and costs are in `COLAB_PLAN.md` (§9 has the measurements).

**Update this file as each step is done.** Status marks: **DONE** (ran, numbers measured),
**TO DO** (not run yet), **NOT WRITTEN** (code missing).

## 3. Credentials, and how MARS and CDS are used

| File | For | Where it lives | How it reaches Colab |
|---|---|---|---|
| `.ecmwfapirc` (url, key, email) | MARS waves | this folder, mode 600, git-ignored | `hc_colab.sh push NAME` pipes it over ssh into `/root/.ecmwfapirc` (600) |
| `.cdsapirc` (url, key) | CDS EDA members, index truth | this folder, mode 600, git-ignored | same, into `/root/.cdsapirc` |
| source.coop S3 credentials (≤ 12 h) | writing pkls and products | `source-coop` CLI cache, `~/.cache/source-coop/` | `hc_colab.sh creds NAME` pipes `source-coop creds --format env` into `/root/.sc.env` (600); re-run before expiry |

Never in `colab exec` code (the Colab CLI records it in `~/.config/colab-cli/history/`), never
printed, never in the repository or on source.coop.

**Requests to MARS and the CDS: one at a time, from Python, never eager.** Both services
rate-limit and can block an account. Rules:

1. Only through the Python scripts listed here (`ecmwfapi` for MARS; the CDS REST client in
   `fetch_era5_l10.py` / `cdsapi` for CDS). No shell loops, no browser-scripted downloads.
2. Every request goes through **`api_polite.polite("mars")` / `polite("cds")`**: a file
   lock per service, so at most ONE request per service is in flight per machine, however
   many builds run in parallel, plus a minimum gap between requests (5 s MARS, 20 s CDS).
   Wired into `era5_state_pkl.wave_fields`, `prefetch_waves.py` and
   `era5_truth_indices.cds_get`. The EDA fetcher (§4) must use it too.
3. Cache first: every fetch checks its target file before requesting (MARS:
   `BC_CACHE/mars_waves/<expver>_all_<date>_<hh>.grib`; CDS: per-request GRIB). A rerun
   never repeats a request.
4. MARS and CDS fetching run on **one** machine or runtime at a time. GPU runtimes never
   call MARS or CDS: they read pkls from source.coop.
5. Request what is used: 2 times per year, only the fields in the state, one request per
   (year, dataset), not per field.

(On 2026-11-12 Phase A ran 4 builds at once without the lock: up to 4 MARS requests in
flight, 40 in total for 20 years. The lock was added on 2026-11-13.)

### 4.2 Perturbed members 002–011 (code written; 2025 built)

Design (README §1, runbook_20261111 §9): member k = control + (EDA member k−1 − EDA mean),
for each of the two times separately. Steps to write, in `era5_eda_perturb.py`:

| # | Step | Notes |
|---|---|---|

| 3 | EDA mean over the 10 members; perturbation = member − mean, per field and time | |

## 9. Problems hit and fixes

| Problem | Fix |
|---|---|
| ARCO read OOM-killed at 52 GB on Colab (recent dask materialises the 1.3 M-chunk graph) | `arco_fields` reads with xarray lazy indexing, no dask |
| earthkit-regrid "No matrix found" on first parallel use | one regrid call before any threads |
| HTTP 520 from source.coop mid-upload (1 of 20) | `sc_io.put` retries the whole upload, reads the size back |
| two workers started together both ran 2025 m002 (claim race; ~0.3 CU wasted) | worker writes the CLAIM, waits 8–12 s, reads it back through the S3 API and proceeds only if its own claim survived; random start stagger |
| Colab allows one ssh connection per runtime; `nohup … &` kept the channel open | `hc_colab.sh` connects per command; background jobs use `setsid -f` |
| `o96_grid` missing on the runtime | `push` includes `fp16FahamuAIFSv2/O96-icechunk-store/*.py` |
| worker retried a failed member in a loop | worker skips members that failed in the same process, stops after 3 failures |
| 4 parallel builds = 4 MARS requests at once; truth script up to 6 CDS jobs | `api_polite.py` lock: one request per service per machine |
| no 0.5° → N320 regrid matrix | perturbations upsampled to 0.25° in numpy, then 0.25° → N320 (§4.2) |
